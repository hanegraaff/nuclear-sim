# Tests

Plan 01 tests the domain model, the camera boundary, source-specific imagery recovery, and the map's visible browser path. Plan 02 adds independent parity data for all 47 devices, pure selection/validation tests including lower-bound and malformed-grouping cases, panel interactions, and reference-viewport snapshots. `unit/` requires no map or browser. `integration/` uses a reversible fake projection in CSS pixels and a fake map event source to verify camera updates, responsive padding, source-specific errors, tile recovery, and style-preserving retry. `e2e/` runs against the built static app and intercepts the imagery URL with `fixtures/satellite-tile.png`, so live imagery, current weather, and tile availability cannot affect the result.

Plan 03 checks all 20 scenario rows and their device and camera requests, bounded scale estimates, and map-controller movement. Its browser path checks keyboard tab navigation, both scenario groups, Hiroshima and Trinity camera movement, device selection, and absence of a strike. It also holds destination tile responses until the test releases them to verify loading feedback, and checks an invalid custom draft across tab switches. The coordinate tolerance of 0.001 degrees allows map rounding while identifying the intended location.

Plan 04 adds pure reducer and application-store tests with explicit monotonic milliseconds for launch, arrival, replacement, stale-frame cancellation, invalid input, and frame cleanup. Geometry tests use representative desktop/mobile viewport sizes, a maximum 14 CSS-pixel step between adjacent samples for a 700 × 450 pixel route, a nonlinear fake projection to verify projection before interpolation, and independent age/seed checks for smoke endpoints. Map integration tests use a reversible fake projection, antimeridian world-copy checks, and an injected deterministic click angle; no imagery is requested. Browser tests freeze the clock after fixed tiles load, capture the 3200 ms first-launch frame, and check controls, invalid yield, replacement, and target/projectile movement during pan. The browser snapshot allows 1% differing pixels to cover minor canvas rasterization differences while still detecting missing missile/reticle/trail artwork.

The geodesy tolerance of 0.01 km for one degree at the equator reflects a rounded reference value; destination round trips use a tighter numerical tolerance because both calculations use the same Earth radius. The browser test asserts the prototype's initial center and zoom, verifies tile requests, and waits for map idle and camera movement rather than sleeping for fixed times. The **2208 × 1276** map snapshot and **1280 × 740 CSS-pixel** panel snapshot have reviewed macOS Chromium baselines in `e2e/*-snapshots/`; the 1% differing-pixel allowance covers minor rasterization variation while still detecting missing imagery, controls, or large layout shifts. A successful map test also writes a desktop screenshot into Playwright's test output for visual review. A different CI operating system needs its own reviewed baseline before enabling this assertion there.

Plan 05 adds `unit/blast.test.ts` for the prototype's 10 kt constants, the rounded 21 kt radius (0.02 km tolerance because the screenshot label is rounded), finite input validation, nested zones, and monotonicity across catalog extremes. `unit/blast-presentation.test.ts` checks exact fireball, severe, moderate, and light color anchors plus fast-first easing. Fake-clock reducer and store tests cover impact at 6500 ms, completion at 11100 ms, replacement during expansion, stale frames, and Reset cancellation. `integration/blast-field-geometry.test.ts` uses fake camera unprojection and real geodesy to check zoom scaling, antimeridian/high-latitude samples, a large-yield boundary, and transparent invalid sky samples. Its Float32 grid values use a 0.01 km numerical tolerance; the 6 km zoom comparison tolerance covers one 2.4 CSS-pixel mask sample. `e2e/blast.spec.ts` uses the fixed tile and browser clock to capture 50 ms after impact, 2300 ms through expansion, and the settled field. Its screenshots were inspected against the two blast prototype images; a 1% pixel threshold covers canvas rasterization variance while direct pixel assertions require at least 30 nearby white-hot core pixels because a settled ruler marker covers the exact center. Browser paths check field replacement, Reset's preserved camera/device, and geographic attachment after pan and zoom. These tests use no live tiles, random angles, or wall-clock time.

Run `npm run verify` from this directory or the repository root. Playwright needs a Chromium browser installed with `npx playwright install chromium`. The root README describes the hosted Site as the user-facing delivery; these commands are engineering checks.

Plan 06 adds `unit/blast-zones.test.ts` for the 21 kt annular area, partition sum, finite extremes, and invalid radii. The 0.2 km² visual tolerance accommodates the reference screenshot's one-decimal display; the 1e-8 km² partition tolerance covers only floating-point subtraction. `unit/launch.test.ts` verifies hover/focus priority, pinning, and cleanup on replacement or Reset. `integration/blast-inspection.test.ts` uses a local equirectangular fake camera to check marker midpoints, fixed ruler bearing through pan and zoom, antimeridian continuity, and prototype cap formatting without live tiles. Its 0.01 km midpoint tolerance accounts for the local linear approximation over a 6 km radius; 0.5 CSS pixels accommodates fake-camera arithmetic. `e2e/blast-inspection.spec.ts` freezes browser time and tiles, tests four visible markers, bounded tooltip placement and edge flipping, keyboard focus through a separate pointer hover, Escape, pinning, map-click isolation, Reset, pan alignment, and ruler direction through zoom. It checks that marker buttons have no visible artwork because marker rings share the ruler canvas. Its two reviewed screenshots use the same 1% rasterization threshold as earlier Canvas baselines.

Plan 07 adds `unit/ground-glow.test.ts` for white-core, warm-falloff, transparent-edge, and invalid-sample behavior. `integration/pitched-ground.test.ts` uses a reversible nonlinear fake camera: the field and all four marker midpoints must agree within 0.25 km, allowing one 2.4 CSS-pixel mask sample at 20 px/km. It also checks the expected north/south perspective compression and reprojects after pan, zoom, and resize. `e2e/pitched-blast.spec.ts` freezes tiles, time, launch position, and viewport, then uses real right-drag pitch and rotation gestures. It checks that the bright center changes from roughly circular to a ground ellipse, the geographic target remains fixed, markers continue to move with pan and remain inspectable after rotation, zoom, and resize. It captures pitched launch, impact, expansion, and settled frames for review; three reviewed camera/expansion baselines differ by at most 1% on the same macOS Chromium environment.

Plan 08 adds `unit/fireball-geometry.test.ts` for growth to the modeled fireball boundary, monotonic radius and opacity, unit-hemisphere geometry, equal horizontal/vertical Mercator dimensions, antimeridian wrapping, and mesh detail. Its 1e-6 unit-radius tolerance covers Float32 mesh quantization; 1e-7 world-coordinate tolerance covers Float32 matrix upload. `unit/fireball-fallback.test.ts` verifies a missing WebGL2 context leaves the 2D renderer optional. `integration/fireball-layer.test.ts` uses a fake MapLibre event source and fixed camera matrix to check frame handoff, replacement and Reset clearing, and layer-add failure. `e2e/fireball.spec.ts` freezes the tile, clock, viewport, and 21 kt launch, then uses a real pitched camera. It reads the retained WebGL drawing buffer to assert a visible dome, tracks its pixel footprint through pan/zoom/resize, verifies the inspection ring is painted above it, and confirms Reset clears it. A second browser path disables WebGL2 only for the fireball canvas and confirms the 2D impact, field, and four markers remain usable. The reviewed expansion and settled baselines allow the established 1% Canvas/GPU rasterization threshold on the same macOS Chromium environment.

The Plan 08 review fix extends `unit/fireball-fallback.test.ts` with fake WebGL allocation failures at fragment compilation, the second geometry buffer, and uniform lookup. Opaque shader, program, and buffer handles let the suite assert that each resource allocated before the failure is deleted while the optional renderer returns `null` and the 2D path remains available. No GPU timing or live browser context is needed for this failure-path test.
