# Verification

The tests protect the simulator's physical units, state transitions, map alignment, and visible user paths. They do not depend on live Esri tiles, random launch angles, current weather, or wall-clock time. Every suite begins with a purpose comment; numerical tolerances are explained beside the assertions that use them.

Run `npm run verify` from the repository root or this directory after installing dependencies and Chromium. It runs type checking, lint, unit tests, integration tests, a production build, and Playwright browser tests. The clean release checkout runs this gate against the exact committed Site tree before publication. Individual scripts such as `npm run test:unit` and `npm run test:e2e` support focused development checks.

## Unit contracts

The catalog suites compare all 47 fixed devices and 20 scenarios with independent prototype data. Selection suites cover custom-yield bounds, malformed separators, tab changes, and invalid IDs. Geodesy and blast suites check coordinate validation, antimeridian wrapping, representative 10 kt and 21 kt radii, ordered zones, and monotonicity. A 0.02 km radius tolerance reflects the prototype screenshot's rounded label; geodesic round trips use tighter numerical tolerances. Zone-area tests use 0.2 km² for the screenshot's one-decimal area and 1e-8 km² for floating-point partition arithmetic.

Fake-clock launch and store suites cover armed, inbound, detonating, and complete phases; replacement; stale callbacks; Reset; simultaneous groups; and stable multi-session entry direction. `mirv.test.ts` checks deterministic distinct targets for all three catalog loadouts, valid polar and antimeridian coordinates, and invalid inputs. `mirv-launch.test.ts` checks one shared carrier, each warhead's individual yield/radii, staggered impacts, cloud rise after the first impact, and whole-group retention. `mirv-flight.test.ts` checks branch endpoints and matching position and velocity at split; its 0.001 CSS-pixel/ms tolerance covers finite-difference curvature over a 0.01 ms probe, far below a visible frame step.

Cloud, overlap, color, fireball, and smoke suites check bounded progress, representative peak heights, order-independent composition, palette progression, screen-space route continuity, GPU cleanup, and conservative offscreen culling. Overlap comparisons at 12 decimal places allow floating-point summation order only; they do not excuse a visible gradient mismatch. Fake WebGL handles test partial resource failures without requiring a GPU.

## Integration contracts

Fake camera and map adapters verify geographic projection, current-world selection across the antimeridian, map padding, imagery recovery, scenario framing, click handoff, and overlay alignment. Field tests unproject a shared ground grid and measure great-circle kilometers; 0.01 km permits Float32 sample storage, while a 6 km zoom-comparison bound covers one 2.4 CSS-pixel mask sample. Inspection tests check that ruler and visible markers use the same camera frame during pan, zoom, pitch, and resize. Cloud-plot tests use a six-decimal interpolation check for CSS-pixel positions and meter-scale ticks.

Combined-field tests cover bounded work chunks, the fixed dense sample tier, retention of an older small W54 effect, and a partial-overlap hue shift rather than alpha-only blending. Fireball-layer tests verify map-matrix handoff and 2D fallback when WebGL is unavailable. Map-controller tests verify mode switching, whole-group rendering, cache invalidation, and the narrow MIRV safeguard: when needed it requests one camera fit without changing geographic targets, and desktop clicks do not trigger that fit. Integration fixtures use reversible fake projections and map events; no live imagery is requested.

## Browser paths and visual baselines

Playwright serves the built static app and intercepts imagery requests with [the synthetic tile](fixtures/README.md). It freezes browser time, uses deterministic launch input, and captures known animation ages. Paths cover device and scenario controls, invalid custom yield, launch and replacement, impact and expansion, pitched map movement, zone hover/focus/pin, multi-launch overlap and legend, cloud readouts, WebGL fallback, Reset, and MIRV separation. The MIRV path captures a shared carrier, split, and three impacts; another path keeps all ten Bulava warheads after multi-to-single switching. A 430 × 844 case requires at least three distinct settled fireball components below the controls. Its 20-pixel component cutoff rejects isolated shader specks while retaining small domes.

Reference-viewport snapshots include 2208 × 1276 for the map, 1280 × 740 for controls, and 1508 × 1080 for animation and effects. Same-environment screenshot comparisons generally allow at most 1% differing pixels for Canvas/GPU rasterization; the MIRV frames use a 0.005 maximum difference ratio and 0.05 per-pixel color threshold. These limits catch missing or misplaced artwork while allowing small edge variation. A different operating system or GPU needs a separately inspected baseline. [Visual reference notes](../docs/visual-reference.md) identify the corresponding read-only prototype images and the limits of fixed-tile comparison.
