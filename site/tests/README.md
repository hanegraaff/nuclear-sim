# Tests

Plan 01 tests the domain model, the camera boundary, source-specific imagery recovery, and the map's visible browser path. Plan 02 adds independent parity data for all 47 devices, pure selection/validation tests including lower-bound and malformed-grouping cases, panel interactions, and reference-viewport snapshots. `unit/` requires no map or browser. `integration/` uses a reversible fake projection in CSS pixels and a fake map event source to verify camera updates, responsive padding, source-specific errors, tile recovery, and style-preserving retry. `e2e/` runs against the built static app and intercepts the imagery URL with `fixtures/satellite-tile.png`, so live imagery, current weather, and tile availability cannot affect the result.

Plan 03 checks all 20 scenario rows and their device and camera requests, bounded scale estimates, and map-controller movement. Its browser path checks keyboard tab navigation, both scenario groups, Hiroshima and Trinity camera movement, device selection, and absence of a strike. It also holds destination tile responses until the test releases them to verify loading feedback, and checks an invalid custom draft across tab switches. The coordinate tolerance of 0.001 degrees allows map rounding while identifying the intended location.

Plan 04 adds pure reducer and application-store tests with explicit monotonic milliseconds for launch, arrival, replacement, stale-frame cancellation, invalid input, and frame cleanup. Geometry tests use representative desktop/mobile viewport sizes, a maximum 14 CSS-pixel step between adjacent samples for a 700 × 450 pixel route, a nonlinear fake projection to verify projection before interpolation, and independent age/seed checks for smoke endpoints. Map integration tests use a reversible fake projection, antimeridian world-copy checks, and an injected deterministic click angle; no imagery is requested. Browser tests freeze the clock after fixed tiles load, capture the 3200 ms first-launch frame, and check controls, invalid yield, replacement, and target/projectile movement during pan. The browser snapshot allows 1% differing pixels to cover minor canvas rasterization differences while still detecting missing missile/reticle/trail artwork.

The geodesy tolerance of 0.01 km for one degree at the equator reflects a rounded reference value; destination round trips use a tighter numerical tolerance because both calculations use the same Earth radius. The browser test asserts the prototype's initial center and zoom, verifies tile requests, and waits for map idle and camera movement rather than sleeping for fixed times. The **2208 × 1276** map snapshot and **1280 × 740 CSS-pixel** panel snapshot have reviewed macOS Chromium baselines in `e2e/*-snapshots/`; the 1% differing-pixel allowance covers minor rasterization variation while still detecting missing imagery, controls, or large layout shifts. A successful map test also writes a desktop screenshot into Playwright's test output for visual review. A different CI operating system needs its own reviewed baseline before enabling this assertion there.

Plan 05 adds `unit/blast.test.ts` for the prototype's 10 kt constants, the rounded 21 kt radius (0.02 km tolerance because the screenshot label is rounded), finite input validation, nested zones, and monotonicity across catalog extremes. Fake-clock reducer and store tests cover impact at 6500 ms, completion at 11100 ms, replacement during expansion, stale frames, and Reset cancellation. `e2e/blast.spec.ts` uses the same fixed tile and browser clock to capture 50 ms after impact, 2300 ms through expansion, and the settled field. Its screenshots were reviewed against the two blast prototype images; a 1% pixel threshold catches missing or changed artwork while allowing canvas rasterization variance. Browser paths also check immediate field replacement, Reset's preserved camera/device, and geographic attachment after pan. These tests use no live tiles, random angles, or wall-clock time.

Run `npm run verify` from this directory or the repository root. Playwright needs a Chromium browser installed with `npx playwright install chromium`. The root README describes the hosted Site as the user-facing delivery; these commands are engineering checks.
