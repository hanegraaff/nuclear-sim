# Verification

The tests protect the simulator's physical units, state transitions, map alignment, and visible user paths. They do not depend on live Esri tiles, random launch angles, current weather, or wall-clock time. Every suite begins with a purpose comment; numerical tolerances are explained beside the assertions that use them.

Run `npm run verify` from the repository root or this directory after installing dependencies and Chromium. It runs type checking, lint, unit tests, integration tests, a production build, and Playwright browser tests. The clean release checkout runs this gate against the exact committed Site tree before publication. Individual scripts such as `npm run test:unit` and `npm run test:e2e` support focused development checks.

## Unit contracts

The catalog suites compare all 47 fixed devices and 20 scenarios with independent prototype data. Selection suites cover custom-yield bounds, malformed separators, tab changes, and invalid IDs. Geodesy and blast suites check coordinate validation, antimeridian wrapping, representative 10 kt and 21 kt radii, ordered zones, and monotonicity. A 0.02 km radius tolerance reflects the prototype screenshot's rounded label; geodesic round trips use tighter numerical tolerances. Zone-area tests use 0.2 km² for the screenshot's one-decimal area and 1e-8 km² for floating-point partition arithmetic.

Fake-clock launch and store suites cover armed, inbound, detonating, and complete phases; replacement; stale callbacks; Reset; simultaneous groups; and stable multi-session entry direction. `mirv.test.ts` checks deterministic distinct targets for all three catalog loadouts, valid polar and antimeridian coordinates, and invalid inputs. `launch-preparation.test.ts` checks that a click freezes device intent and geographic targets before camera framing. `mirv-launch.test.ts` checks one shared carrier, each warhead's individual yield/radii, staggered impacts, cloud rise after the first impact, and whole-group retention. `mirv-carrier-plan.test.ts` checks a normal 60% split, earlier or extended approaches when targets would lie behind the carrier, and polar or antimeridian fixtures; its 0.01 km forward-progress tolerance permits small local projection error while rejecting a kilometer-scale reversal. `mirv-projection-safety.test.ts` samples branches under tested pitch and bearing combinations to catch projected reversals missed by a geographic tangent alone. These finite fixtures do not prove forward motion under every nonlinear camera state. `mirv-flight.test.ts` checks branch endpoints and matching position and velocity at split; its 0.001 CSS-pixel/ms tolerance covers finite-difference curvature over a 0.01 ms probe, far below a visible frame step.

Cloud, overlap, color, fireball, and smoke suites check bounded progress, representative peak heights, order-independent composition, palette progression, screen-space route continuity, GPU cleanup, and conservative offscreen culling. Overlap comparisons at 12 decimal places allow floating-point summation order only; they do not excuse a visible gradient mismatch. Fake WebGL handles test partial resource failures without requiring a GPU.

Fallout unit suites cover reproducible latitude-band wind and hemispheres, positive-yield scaling and bounds, curved geodesic centerlines, antimeridian displacement, deterministic physical-coordinate field samples, geographic/local scalar-kernel equivalence across latitude and world wrap, nested screening spans, and finite intensity in [0,1]. Audible unit tests cover yield monotonicity and Earth-surface bounds, invalid inputs, contiguous experience bands, and smooth falloff through a 12% soft tail. Effect-view suites verify settled-only switching, pending-launch guards, conventional Fallout exclusion, retained mixed/MIRV eligibility, per-warhead footprints, Reset/new-launch return to Blast, inspection precedence, and model-derived legend values. These tests validate deterministic screening contracts, not printed Gy or dB labels as computed measurements.

## Integration contracts

Fake camera and map adapters verify geographic projection, current-world selection across the antimeridian, map padding, imagery recovery, scenario framing, click handoff, and overlay alignment. Field tests unproject a shared ground grid and measure great-circle kilometers; 0.01 km permits Float32 sample storage, while a 6 km zoom-comparison bound covers one 2.4 CSS-pixel mask sample. Inspection tests check that ruler and visible markers use the same camera frame during pan, zoom, pitch, and resize. Cloud-plot tests use a six-decimal interpolation check for CSS-pixel positions and meter-scale ticks.

Combined-field tests cover bounded work chunks, the fixed dense sample tier, retention of an older small W54 effect, and a partial-overlap hue shift rather than alpha-only blending. Fireball-layer tests verify map-matrix handoff, 2D fallback when WebGL is unavailable, and invalidation of a stale matrix on synthetic visibility and focus events. Map-controller tests verify mode switching, whole-group rendering, cache invalidation, bounded MIRV framing retries with a recoverable failure, and a one-time narrow fit without changing geographic targets. Integration fixtures use reversible fake projections and map events; no live imagery is requested.

Fallout rendering tests require all ten retained fields to receive preview samples before refinement, and count model calls to prove that completed textures survive camera changes and resize without resampling. They also cover shared texel allowances, antipodal-chart transparency, antimeridian projection, invalid horizon faces, valid viewport-enclosing faces at high zoom, refinement cancellation, and geographic marker alignment. Audible integration tests use a reversible fake camera at the antimeridian to check four geodesic markers and ruler movement under pan and zoom, palette channel continuity, and bounded order-independent overlap. A separate fake-camera and fake-animation-frame suite checks conservative overhead culling, full-mask fallbacks for pitch and ambiguous wrap, a complete first-entry preview within 8,000 scene-wide evaluations for up to ten deliveries, sampling beyond the starting viewport when a hearing circle crosses it, retention of that overscanned preview if a starting-viewport mask finishes first, a bounded full-world preview for a 20 Tt capped field, the 24,000-cell full-mask chunk budget, cancellation of an obsolete pan job, and eventual visibility of an older small field after many retained strikes. It verifies that the preview reprojects during camera ease and is replaced only after settled-camera refinement. The 350 ms browser baseline and checks at 120, 350, and 550 ms reject a long straight preview-mask edge through the visible field; a 20 Tt path checks green alpha across repeated-world ground points at the same times. These finite fixtures establish the sampled camera and timing contracts; they do not impose a machine-specific frame-rate or completion-time threshold. Controller regressions distinguish explicit single-view Blast-camera restoration from a replacement launch that must preserve the clicked camera, and verify unchanged multi-mode cameras across view switches.

## Browser paths and visual baselines

Playwright serves the built static app and intercepts imagery requests with [the synthetic tile](fixtures/README.md). It freezes browser time, uses deterministic launch input, and captures known animation ages. Paths cover device and scenario controls, invalid custom yield, launch and replacement, impact and expansion, pitched map movement, zone hover/focus/pin, multi-launch overlap and legend, cloud readouts, WebGL fallback, Reset, and MIRV separation. The MIRV path captures a shared carrier, split, and three impacts; another path keeps all ten Bulava warheads after multi-to-single switching. High-zoom tests check immediate pending reticle, brief pre-launch framing, selection frozen across the delay, Reset and replacement cancellation, and multi-mode click order. A 430 × 844 case requires at least three distinct settled fireball components below the controls. Its 20-pixel component cutoff rejects isolated shader specks while retaining small domes. The narrow screenshot gate hides only MapLibre's raster canvas after a separate full-imagery capture; controls, attribution, fields, fireballs, ruler, and markers remain visible for a stable overlay comparison.

Fallout browser journeys cover a settled nuclear plume, four focusable markers and pin/Escape interactions, in-motion pan and zoom, high zoom through the supported range, reversible view switching, new-launch target visibility and Reset cleanup, conventional-only exclusion, and nuclear-only rendering within a mixed multi scene. A 430 × 844 pointer path checks that both tabs remain below the instrument stack and do not launch an unintended strike. Pitched Fallout baselines use both 2208 × 1276 CSS pixels at DPR 1 and 1299 × 751 CSS pixels at DPR 1.7, the latter approximating the prototype's output composition. Each allows a 0.008 differing-pixel ratio with a 0.05 per-pixel color threshold for small Canvas edge variation; manual comparison still records the slimmer pitched silhouette against `Fallout.png`. The motion regression requires more than 45% of the settled field's visible pixels during small camera gestures: this tolerates edge cropping while rejecting a glow-only frame. High-zoom checks keep valid large faces visible rather than treating their screen size as a wrap discontinuity. These work-count and visibility contracts are enforceable without a machine-specific frame-rate threshold.

Audible browser journeys use the same fixed tile and fake time to inspect a settled green field, four focusable single-view markers, illustrative dB popup, camera restoration on explicit Blast selection, new-launch return to Blast, two overlapping fields with a fixed legend during camera movement, Reset, and reachable view tabs at 430 × 844. The single and two-impact multi baselines use 2208 × 1276 CSS pixels at DPR 1 and allow a 0.008 differing-pixel ratio with a 0.05 color threshold for small Canvas raster variation. Their top-down fixture state differs from the pitched ten-impact `Additive Blasts.png` reference; [visual notes](../docs/visual-reference.md) record the inspected comparison.

Reference-viewport snapshots include 2208 × 1276 for the map, 1280 × 740 for controls, and 1508 × 1080 for animation and effects. Same-environment screenshot comparisons generally allow at most 1% differing pixels for Canvas/GPU rasterization; the MIRV frames use a 0.005 maximum difference ratio and 0.05 per-pixel color threshold. These limits catch missing or misplaced artwork while allowing small edge variation. A browser fireball path uses synthetic `visibilitychange` and `focus` events plus a real viewport resize to test fresh projection and alignment. Chromium did not emit native background or operating-system focus events here, so this test does not prove a real application switch. A different operating system or GPU needs a separately inspected baseline. [Visual reference notes](../docs/visual-reference.md) identify the corresponding read-only prototype images and the limits of fixed-tile comparison.
