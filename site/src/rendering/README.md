# Rendering

Rendering adapters translate immutable model results into MapLibre camera coordinates and, in later plans, Canvas/WebGL effects. The model never depends on this area.

Plan 01 provides the MapLibre satellite style/factory, `MapCameraAdapter`, and `SatelliteMapController`. The camera adapter projects and unprojects geographic points through a small interface that tests can fake. The controller is the UI-facing map API: `createSatelliteMapController` mounts the map, callbacks publish readiness and camera position, `retryImagery` reloads only the satellite tiles, and `dispose` removes listeners and the map. MapLibre objects stay inside this area. Readiness waits for MapLibre's idle event so live tiles can fill the viewport. A successful satellite tile clears a transient imagery error and returns to loading until idle; errors from other sources do not claim the imagery is unavailable. Plan 02 uses `setPanelsVisible` and resize-aware padding to keep the camera's visual center clear of the left control panel. The raster style declares imagery attribution. The factory sets MapLibre's bundled worker URL before creating a map, as required by MapLibre's Vite integration.

Plan 03 adds `focusScenario`: it turns a supplied center and modeled horizon into the prototype's viewport-dependent zoom and a 650 ms camera ease. Scenario navigation reports imagery loading until the destination source reaches idle, including when uncached tiles are slow. `scenarioZoom` contains only projection and viewport framing; the yield-based horizon comes from the domain layer.
