# Rendering and map

This package turns immutable geographic launch frames and model results into visible map effects. MapLibre owns the satellite camera and imagery; Canvas draws ground fields, missiles, smoke, the cloud instrument, and inspection artwork; a small MapLibre-aligned WebGL2 layer draws the raised fireballs. Neither the map controller nor a painter chooses device yields or advances the application clock.

`MapCameraAdapter` projects and unprojects geographic points and selects a nearby world copy across the antimeridian. `SatelliteMapController` is the narrow UI-facing map API. It creates the map, translates clicks into geographic flight routes, sends readiness/camera/inspection callbacks, focuses a scenario, accepts scene frames, retries failed imagery tiles, and disposes listeners and GPU resources. Imagery readiness waits for MapLibre idle after visible tiles load. Source-specific tile errors do not replace the map style or erase effects. The raster source keeps Esri attribution visible. On page visibility or window focus return, the controller drops any old fireball matrix, resizes the map, and requests a new map frame; it does not reuse projection data captured before the page was hidden.

The controller's `setMapTone` applies the prototype's separate day or night saturation, contrast, and brightness values to the satellite raster after map load; it leaves effect painters and attribution alone. `setPanelsVisible` removes the 380 px left camera padding on desktop or 80 px top padding on narrow maps while the control stack is hidden, then restores the appropriate padding when shown. Each padding change requests a camera repaint so geographic fields and inspection markers track the new projection. Its keyboard launch action uses the current map center as the target and follows the normal route preparation. React passes these application choices to the controller through its narrow API; the renderer does not decide whether the panels should be shown.

A click's device and geographic targets are prepared by the application before camera movement. The controller tries a viewport-edge carrier route from the current camera, then checks projected branches for forward progress at the current pitch and bearing. If no candidate is acceptable, it paints the target reticle immediately, queues that immutable click, and eases the map for about 450 ms before retrying. Multi clicks retain order; a new single-mode click replaces the pending one. Reset cancels the queue, and a bounded sequence of unsuccessful fits reports a recoverable “zoom out and try again” message. The controller can also fit an otherwise hidden settled MIRV spread on a narrow viewport, using a numeric clear-area measurement from the UI rather than reading UI markup. These camera changes never move the modeled targets. Once launched, the carrier start, curved control, and target are stored as geographic coordinates, though the start came from a viewport edge. Each frame projects them through the current camera; the shared carrier separates into continuous branches for distinct targets. [Animation rendering](animation/README.md) explains missile, smoke, flash, and fireball contracts.

The controller switches effect painters from the application-owned active view. In single mode, entering Fallout, Audible, or Visible saves the Blast camera and eases to the application-provided geographic range; selecting the Blast tab restores its center, zoom, pitch, and bearing. An accepted new click clears the saved frame so the automatic return to Blast keeps its target in view, including while a MIRV awaits its own framing. Multi mode changes views without moving the camera. Fallout, Audible, and Visible hide missile/fireball/Blast inspection artwork while retaining the underlying launch data. View changes, replacement, Reset, and disposal cancel pending field work so an old composition cannot repaint a new scene. Reduced-motion launch frames suppress smoke, pulses, flashes, and shock rings and freeze the dome texture, without changing the geographic field or settled result.

[Effect rendering](effects/README.md) keeps physical sampling separate from display projection. Blast caches visible-ground distance and color samples; its combined compositor uses one shared ground grid and bounded chunks for overlapping groups. Camera changes invalidate those projection caches. Fallout caches complete strike-local scalar textures and geographic contour segments independently of the camera. Every retained plume has a coarse preview before bounded refinement; camera movement reprojects its geographic mesh into a shared additive scalar mask, then applies the palette. It does not discard valid model samples on pan, zoom, pitch, bearing, or resize. Audible and Visible share a bounded range renderer: each samples its own model radius into one fixed-resolution screen mask in cancellable chunks, reprojects a completed mask during camera movement, then builds and atomically swaps a settled-camera mask. Green hearing and blue fireball-sightline palettes belong to rendering; each radius and experience span belongs to the model and application. The white-yellow Fallout glow, white-gold Blast center, and 3D dome are optical artwork separate from normalized field values. A failed WebGL context leaves the 2D flash and field usable.

[Inspection overlays](overlays/README.md) project geodesic zone rings, rulers, and markers through the same camera. Their visible lines paint in a transparent canvas above the dome; UI-owned hit targets use the returned CSS-pixel positions. Fallout uses a curved geodesic H+24 ruler with four model-derived downwind spans; Audible and Visible use straight geodesic range rulers and four model spans without hard field boundaries. Multi mode removes geographic rulers and contours and presents a camera-center distance scale with a fixed legend; legend values describe the newest eligible delivery. Turning multi mode off keeps the latest whole group: every retained impact remains visible, with inspection attached to the latest delivery. The independent [cloud renderer](cloud/README.md) receives application-derived height and phase, never a map camera.

Tests use reversible fake projection, fake map events, fixed tiles, and deterministic clock frames. The visible result should stay attached to geographic ground as the camera moves; screen pixels are only a drawing output.
