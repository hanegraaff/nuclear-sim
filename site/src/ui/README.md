# User interface

React mounts the full-viewport map and displays selection, launch status, cloud height, and inspection controls. Components subscribe to `SimulatorStore` snapshots and dispatch semantic actions; they do not calculate physical radii, branch targets, overlap intensity, or animation time. Packaged Geist fonts, compact charcoal panels, coral controls, and dense mono labels reproduce the prototype's visual hierarchy.

`DevicePanel` contains keyboard-accessible Scenario and Device tabs, grouped native selectors, custom-yield input, Reset, and a pressed-state Multi-Launch Mode button. Selecting a scenario prepares a device and requests camera movement without launching. Invalid custom text stays available for correction but prevents a map launch. The status announces inbound, expanding, and complete phases; a MIRV status includes impacted and total warheads. A pending MIRV camera ease keeps Reset enabled even before a launch group exists. A control click never reaches the map launch target.

`MapViewport` mounts and disposes the rendering-owned controller, passes geographic launch frames and camera requests across the boundary, and receives readiness, camera, and inspection geometry through callbacks. It asks the application to prepare and freeze a click's device and geographic targets before the map frames a MIRV. A pending target reticle paints immediately while an unsafe route is reframed; the selected device may change during that delay without changing the queued launch. Reset cancels pending clicks, and exhausted framing attempts show a recoverable error message. Map imagery errors show a separate retry action without blocking the rest of the UI. For a narrow MIRV group, the UI supplies the lower edge of the control stack in CSS pixels so the map controller can frame otherwise hidden impacts; rendering does not inspect a React class or component. The map and effect canvases remain transparent to pointer input except at intentional controls and marker targets.

In single mode, `BlastInspectionOverlay` positions transparent focusable hit targets at the renderer's four visible marker rings after expansion. Hover, focus, click-to-pin, and Escape update inspection state. One tooltip explains the current zone and its modeled span and area, clamped inside the viewport. In multi mode, `MultiLaunchLegend` provides four fixed gradient markers with the same interactions and a camera-derived distance bar; its quantitative span belongs to the latest individual strike, while the colors show combined field intensity. Switching back displays the newest whole group and its latest delivery's ruler and markers.

`EffectViewSelector` exposes only the implemented Blast and Fallout tabs after the retained scene settles; Fallout eligibility comes from application state. The selector sits at the upper right on a wide viewport and below the instrument stack at the lower left on narrow screens so pointer controls remain reachable. Its clicks stop map launch input. `FalloutInspectionOverlay` uses renderer-provided marker positions in single mode and application-provided newest-nuclear-delivery zones in the multi legend. The four bands support hover, keyboard focus, pinning, and Escape, with viewport-bounded popups explaining the prototype Gy label, downwind span, and approximate area. React performs no fallout physics. `MapViewport` displays the surface-burst H+24 and climatological-wind qualification while Fallout is active. A new launch returns to Blast at the clicked camera and clears stale inspection; only an explicit Blast-tab selection restores the saved single-view camera.

`CloudProfileMonitor` sits below the controls. Text announces the current modeled height and phase; a decorative, assistive-technology-hidden Canvas paints the scale and silhouette. It follows the first ignited warhead in the latest MIRV group and labels height as per warhead. Nuclear and conventional devices receive different plume wording. Reset returns the monitor to standby without changing selection, mode, or camera. The compact layout shortens the plot on a narrow viewport; broader responsive behavior remains on the roadmap.
