# Application state

This package owns selection, launch groups, phases, inspection state, and clock progression. It imports catalog and pure domain functions, but no React component, map instance, Canvas, or WebGL object. UI components dispatch semantic actions and render immutable snapshots; drawing code consumes derived launch frames.

`deviceSelection.ts` validates fixed catalog IDs and custom yields. The default is Fat Man. Custom input accepts finite 0.000000001–1,000,000,000 Mt and consistent three-digit separators; an invalid draft remains visible when the user returns to the Device tab and cannot launch. `scenarioSelection.ts` composes that selection with the Scenario tab. Selecting one of 20 scenarios prepares a device and issues a geographic camera request without detonating. Changing device clears the selected scenario.

`launchPreparation.ts` freezes the selected device identity, aggregate yield, and deterministic geographic MIRV targets at the map click, before any camera ease. Its `PreparedLaunch` is independent of screen pixels. `mirvCarrierPlan.ts` uses geographic distances to preserve the normal 60% split when possible and choose an earlier split or longer incoming approach when a target would sit behind the carrier. It keeps the impact targets unchanged. `launch.ts` then defines `LaunchGroup` as one committed click; `reduceSimulator` stores the planned shared carrier, split time, each per-warhead yield and radii, and the monotonic start time. A normal group has one delivery; a MIRV group has three or ten. Single mode replaces the prior group, including an active flight. Multi mode appends groups, and turning it off retains the latest whole group. `launchFramesForState` derives every delivery's age, so one missile can approach while older fields expand or remain settled. Aggregate phase reports active detonation before inbound flight; Reset clears groups and inspection without changing device, mode, or map camera.

`SimulatorStore.ts` owns the injected monotonic clock, one cancellable animation-frame request, subscriber notification, and launch validation. `prepareLaunchAt` captures click intent; `launchAtWithIntent` commits that same choice after any map framing, even if the user changes the selector meanwhile. The store mirrors whether a framing click is pending so Reset remains available before the first launch frame. The rendering-owned controller queues the clicks themselves. The store ignores stale callbacks after replacement or Reset and stops scheduling when no group is active. A multi session keeps one general carrier-entry bearing across clicks; each target and route remains separate. Focused tests use fake time and deterministic angles, so wall-clock scheduling and random entry directions cannot affect results.

Each nuclear delivery freezes a `FalloutFootprint` at creation, using its target, per-warhead yield, and deterministic seed; MOAB and FOAB have none. The reducer owns the active `blast` or `fallout` view. It permits a view change only after all retained deliveries settle and no framing click is pending, and derives Fallout eligibility from those deliveries rather than the current selection. New launches and Reset return to Blast. A mode change retains Fallout only if the retained whole group still contains a nuclear footprint.

`effectPresentation.ts` derives a geographic Fallout camera center and kilometer horizon from the first retained nuclear footprint. The map adapter converts this into a camera frame; it also owns saving/restoring the Blast camera in single mode and preserving the camera in multi mode. The same application module derives immutable multi-legend spans and areas from the newest nuclear delivery, keeping model calculations out of React. Neither presentation describes a combined dose.

The reducer stores separate Blast and Fallout hovered, focused, pinned, and derived active inspection IDs rather than popup pixels. Hover takes precedence over focus, then a pinned marker; Escape clears inspection. `cloudPresentationForState` reads the latest group and its first ignited warhead to derive phase, modeled height, nuclear or conventional wording, and per-warhead labels from the pure cloud model. Before ignition it shows standby; after Reset the selected device again supplies the standby scale. The renderer receives this presentation object and does not calculate cloud physics or own the clock.
