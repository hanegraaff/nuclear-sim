# Application

This area owns simulator state transitions and validation independently of React and renderers. `deviceSelection.ts` accepts semantic selection and custom-input actions, and `resolveDeviceSelection` returns a catalog or custom device only when its yield is valid. The initial choice is Fat Man; switching away from custom input preserves its draft. Unknown catalog IDs are rejected. Custom yields must be finite and fall between 0.000000001 and 1,000,000,000 Mt. Commas, underscores, or spaces are accepted only as consistent three-digit grouping separators; malformed grouping is rejected instead of silently changing the yield. The map's loading state remains local to its renderer and UI.

`scenarioSelection.ts` composes device selection with the selected tab and scenario. A scenario action changes the device and produces a sequenced camera request containing only a geographic center and horizon in kilometers. Switching tabs preserves the selection; changing a device clears the scenario. No action creates a strike.

`launch.ts` composes selection with one active launch. `reduceSimulator` accepts a geographic route and device profile at the click, advances elapsed milliseconds using injected monotonic time, and ignores stale frame IDs after replacement or Reset. It stores the route and target in degrees, never screen pixels. This plan reaches `complete` at 6.5 seconds and keeps the reticle; Plan 05 adds detonation and its effect model.

`SimulatorStore.ts` owns the injected monotonic clock, one cancellable frame request, launch validation, and subscriber notification. It cancels an old request when a launch is replaced or reset and stops scheduling when the blast settles at 11.1 seconds. `nextLaunchAngle` gives each launch a reproducible but different edge-entry angle. React only subscribes to snapshots and dispatches semantic actions; fake-clock tests drive the store without a browser.

Plan 05 extends each `Launch` with immutable modeled radii and a 4.6-second blast duration. The reducer transitions `armed → inbound → detonating → complete` at 6.5 and 11.1 seconds after launch. A later click replaces any phase with a new inbound launch; Reset clears the strike while preserving selection. Elapsed time remains monotonic and stale frame callbacks cannot advance a replaced launch.
