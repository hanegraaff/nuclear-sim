# Nuke Simulator Site source

This directory contains the static Site source for the workspace roadmap. The published Site is the user-facing application. Plans 01–03 provide a full-screen satellite map and prototype-style Scenario and Device controls. Plan 04 adds map targeting, a red crosshair, and an incoming missile. Plan 05 adds an impact flash, expanding single blast, and Reset. Plan 06 adds the settled blast ruler, zone outlines, and inspection markers. Plan 07 grounds the center glow on pitched map views. Plan 08 adds a textured fireball dome that grows from the modeled impact and follows the map camera. Plan 09 adds the separate cloud-profile instrument below the controls. Plan 10 adds additive multi launch. Users can pan, zoom, right-drag upward to pitch, choose any of the 47 fixed devices, enter a custom yield, or select one of 20 scenarios to move the map and prepare its device. A click replaces the previous strike in single mode. Multi-Launch Mode keeps each click, including earlier blasts while another missile is inbound; the missiles approach from one general side. Overlap moves map color toward warmer legend bands as well as increasing brightness. Switching back keeps and displays the newest whole click group. The cloud instrument follows the latest launch and Reset clears all strikes and returns it to standby. In single mode, hover or focus a zone marker for its description and modeled span; click to pin its popup and press Escape to clear it. In multi mode, use the lower-left four-band legend for the same hover, focus, and pin interactions; its span describes the latest strike. Alternate views and MIRV separation arrive in later plans.

## Engineering setup

Requires Node.js 22.13 or newer. In this directory, run `npm ci`, then `npx playwright install chromium` if the test browser is not installed. Run `npm run verify` for type checking, lint, unit and integration tests, a production build, and browser checks. `npm run dev` and `npm run preview` are optional engineering tools; they are not required for using the published Site.

## Source layout

- `src/catalog/`: exact grouped device choices and per-warhead MIRV data.
- `src/domain/`: pure geographic, blast-radius, annular area, cloud-height, and bounded overlap calculations.
- `src/application/`: selection, click groups, independently timed launches, and cloud values derived from launch time.
- `src/rendering/`: MapLibre setup, camera projection, single and combined Canvas fields, cloud plot, WebGL fireballs, and inspection overlays.
- `src/ui/`: React mount, controls, map states, cloud instrument, and accessible marker/legend popups.
- `tests/`: deterministic unit, integration, and browser checks.

Each click remains its own geographic launch group with its selected yield and modeled radii. A pure overlap function combines their local intensities; a separate renderer moves overlapping samples toward warmer palette hues without creating a larger virtual weapon. The application store advances their shared clock and holds one entry direction during a multi-launch session. The renderer unprojects one bounded viewport grid, measures each strike against that shared ground, and composes large scenes in chunks. This limits stored samples and work per repaint; dense fields may look softer and finish drawing across several frames after a camera change, but every visible strike contributes. The lower-left distance bar estimates scale at the camera center; at pitch it is a reference, not a measurement at every screen point. The cloud height comes from a per-impact yield and burst-height profile. This numerical estimate never reads the map camera or Canvas; application state turns the latest blast's elapsed time into a normalized rise, and the instrument renderer paints the resulting scale and silhouette. The map uses Esri World Imagery with source attribution visible in the map control. The map service is external; unavailable imagery produces a retry notice. The Site is configured as a static `dist/` build in `.openai/hosting.json`. The prototype folders stay outside this source repository and are read only. See `docs/model.md` for yield units and limits and `docs/visual-reference.md` for staged differences from the prototype.
